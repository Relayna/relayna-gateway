# v1.6.0 release benchmark

The six native amd64 adaptive searches on 23 November 2026 UTC completed
**239 fresh-pod trials**. Each selected setting has three
resource-stable, HTTP-clean confirmations. The searches used the default
admission path with upload waiting disabled.

## Runtime and method

[Runtime and harness `0bbac005847b`](https://github.com/sarattha/relayna-gateway/commit/0bbac005847be624b260d1fd57916237d1a6232b)
were built from committed source on separate native GitHub-hosted runners.
Each trial used two fresh Gateway pods, each capped at **2 CPUs, 1 GiB memory,
and a 512 MiB serialized-body budget**. Host, Docker, candidate image, and kind
node architectures were amd64. Each driver sent exact-sized JSON directly
to both pods over HTTP/1.1. The mock verified body length, hash, and credentials,
paused reads for ten seconds, and delayed its response by two seconds. Gateway
used PostgreSQL and Redis. Client, condition, and trial deadlines were 180,
300, and 600 seconds.

Run one search per size using the same committed source:

```sh
for size in 5 10 20 40 80 100; do
  gh workflow run body-admission-benchmark.yml --ref t3/litellm-audio-transcriptions-ui \
    -f architecture=amd64 -f mode=full -f body_mib="$size"
done
# The workflow runs the native CLI once for its selected size.
scripts/bench-body-admission --json run --build --body-mib 5 \
  --repetitions 3 --output target/release-benchmarks/v1.6.0/5mib
```

## Memory and capacity

Peaks are per Gateway pod. Headroom is 1,024 MiB minus the largest cgroup
memory peak across the selected confirmations. The audit replays each original
trial, verifies fixture and image provenance, and checks that each confirmation
uses two fresh pods. Each adjacent setting recorded an OOM in one of its three
observations. The table treats the selected settings as tested lower bounds.
Use memory headroom when interpreting these observations.

## Same-runner comparison with v1.5.0

The [comparison workflow](https://github.com/sarattha/relayna-gateway/actions/runs/45212589014)
built the candidate and used v1.5.0 at immutable index digest
`sha256:fc006aca24ce5891cb9da18e0cd849cc405e367acf6a21b1c86106d77346ad28`.
Both used 5 MiB JSON, eight slots per pod, 16 offered per pod, and three
fresh-pod trials on the same Intel Xeon 6975P-C host. Round-trip times include
12 seconds of fixture delay. The two versions verified the same number of
uploads, with a 4 ms difference in worst per-trial p95 across three runs.
