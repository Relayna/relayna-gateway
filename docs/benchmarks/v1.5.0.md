# v1.5.0 release benchmark

The six native amd64 resource searches on 19 November 2026 UTC completed **265 fresh-pod trials**. Each selected setting has at least three resource-stable confirmations. The release study used the default admission path with waiting disabled. A separate native arm64 burst study exercised the opt-in queue.

## Runtime and method

[Gateway and harness 5174ae0610b4](https://github.com/sarattha/relayna-gateway/commit/5174ae0610b42c0891b93f54cd7d78a659c0fec8) were built from committed source on each runner. Each trial ran two fresh pods with **2 CPUs, 1 GiB memory and a 512 MiB serialized-body budget each**. The driver sent exact-sized JSON directly to both pods using HTTP without TLS, compression or retries. The mock verified upstream body length, digest and credentials, paused reads for ten seconds and delayed the response by two seconds. Deployment used real PostgreSQL and Redis. The client, condition and outer deadlines were 180, 300 and 600 seconds.

Each size ran separately on the feature branch at the runtime commit above. For each workflow dispatch, set `size` to one of 5, 10, 20, 40, 80 or 100. Host, Docker, image and kind-node architecture were amd64. The provenance includes individual host details, image identities, harness hashes and timestamps.

```sh
size=5
gh workflow run body-admission-benchmark.yml --ref feat/bounded-upload-wait \
  -f architecture=amd64 -f mode=full -f body_mib="$size"
scripts/bench-body-admission --json run --build --body-mib "$size" \
  --repetitions 3 --output target/body-capacity
```

## Memory and capacity

RSS and cgroup peaks are measured per gateway pod. Headroom subtracts the observed cgroup peak from the 1,024 MiB limit. Capacity counts include partially uploaded bodies. The audit calls a setting a confirmed resource edge only when all three or more adjacent trials hit an OOM and no lower-slot failure contradicts it at the same offered cohort.

| 5 | 94 | 3 / 3 | 94 | 95, 1/3 | 923.23 / 1004.81 | 19.19 | tested lower bound |
| 10 | 46 | 3 / 3 | 46 | 47, 1/3 | 931.07 / 1019.55 | 4.45 | tested lower bound |

| 100 | 11 | 3 / 3 | 11 | 12, 1/3 | 968.62 / 973.83 | 50.17 | tested lower bound |

The tightest confirmation left **1.96 MiB** of headroom at 20 MiB. Keep the
default eight slots and reserve margin for workload variation when tuning.
For the 100 MiB cohort, v1.5.0 confirmed 11 slots per pod on an Intel Xeon
runner and v1.4.0 confirmed 32 on an AMD EPYC runner. Both studies found a
tested lower bound, and the hardware differed. The comparison cannot establish
how much of the change came from the gateway.

## Opt-in upload queue

Two gateway pods on an Apple M1 Pro received 240 requests in the first 250 ms of each second. Each pod had eight active slots, 192 waiters, a ten-second queue deadline, two CPUs and 1 GiB of memory. Four clients sent nine sizes of synthetic production-shaped JSON from 8 KiB to 100 MiB. Two 20-second trials and one 60-second trial used the same body sequences as the earlier PR study. The streaming mock paused reads for 250 ms and delayed responses by 500 ms.

The v1.5.0 candidate verified **24,000 / 24,000** uploads. Pooled verified p95 was **1.59 s**, the busiest gateway container peaked at **406.0 MiB**, and the trials recorded **0 HTTP 503s**. Container peaks exclude pod sandbox overhead. The trials had zero transport errors and zero restarts. The earlier feature commit verified 24,000 of 24,000 at 1.57 s p95 and a 388 MiB peak. The earlier LiteLLM and sustained-overload comparisons are reported against that feature commit. ## Verification

The runtime commit passed all 17 executed CI checks, including the ten-minute
HTTP, SSE and WebSocket monitoring check. Local verification passed 571 tests
with PostgreSQL and Redis. The v1.5.0 process opened the v1.4.0 database
and reported ready with all 45 applied migration checksums intact.
[CI checks and upgrade evidence](https://sarattha.github.io/relayna-gateway/assets/releases/v1.5.0/gateway-1.5.0-verification.json).
